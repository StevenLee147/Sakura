# Sakura 0.6.0-beta · 全项目修复与交付检查

本轮保留「左侧四轨 + 右侧鼠标」的混合玩法和樱花主题，完善离线游戏从首次启动、选曲、演奏、暂停、结算到编辑与数据恢复的完整流程。未把后续联网规划改成当前功能。

## 审查发现与修复

| 范围 | 原问题 | 本版处理 |
|---|---|---|
| 判定/计分 | 长按尾部、滑动节点与总判定数不一致，部分漏判重复结算 | 统一 PlaySession；输入、自动演示、回放共用引擎；百万分精确归一化；幂等结束 |
| 时间/暂停 | 帧时间累计、暂停输入残留与长按恢复可能产生偏差 | 音频游标驱动歌曲时间，输入事件年龄补偿；倒计时、焦点暂停、恢复容错 |
| 曲库 | 基础筛选、练习与回放入口不完整 | 搜索/排序/收藏/难度分页；记住选择；分段变速循环；最近回放；导入暂存提交 |
| 设置 | 项目与实际行为脱节，缺少保存/放弃、校准及数据管理 | 六页设置；实时预览、重置、冲突键位检查、关闭确认；真实音频节拍校准 |
| 视觉 | 菜单、结算、过渡、命中反馈风格不统一；背景柔化为空实现 | 夜樱月光场景、花瓣、柔光、轨迹、命中环、键位脉冲；六类转场；缓存背景柔化；减少动态效果 |
| 游戏流程 | 加载错误、重新开始、编辑器试玩返回不完整 | 明确失败提示；保留难度/模式重试；编辑器使用真实双区引擎并返回原编辑器 |
| 工房 | 输入字段、异步文件对话框、保存和难度操作不稳定 | 共用 UTF-8 输入；回调 mailbox 生命周期；保存/放弃/取消；属性编辑撤销；自动恢复副本 |
| 内容 | 短循环测试音轨与稀疏内容 | 四首 40 小节原创程序合成曲目与八张主谱，加两首训练曲；全曲覆盖与谱面冲突检查 |
| 数据 | 相对工作目录写存档，迁移/恢复不完整，旧规则成绩混用 | 独立用户目录、原子文件写入、schema 3、事务保存、hash 区分谱面、先备份后恢复 |
| 回放 | 缺乏真实输入重现及内容校验 | `.skr` JSON v1，内容 hash、参数校验、窗口缩放事件、暂停恢复输入重现；辅助模式隔离 |
| 音频/图片 | OGG 缺解码/准确时长与跳转，JPG 选择器与构建不一致 | stb_vorbis 可跳转解码、独立频谱游标；显式启用 JPEG feature；四种音频和图片实际验证 |
| 性能 | DFT、每帧纹理/字体开销、逐音符过期扫描、重复查询 | 1024 点 FFT 30 Hz，文字/字号缓存，几何批处理，活动游标与纹理引用计数，成绩缓存 |
| 交付 | 运行目录依赖、缺成就配置与依赖说明 | exe 基准资源路径、UTF-8 manifest/图标、完整 ZIP 打包、CRT 与许可证、中文玩家指南 |

## 验证记录

本机 Windows x64、MSVC v143、SDL GPU renderer；CMake 生成 Debug 和 Release。逻辑测试通过 **61/61**，两种配置均通过。主要覆盖判定窗口、Hold/Slider、精确满分、实际输入回放、窗口宽高比、暂停恢复、练习区间、FFT、SV 连续性、损坏数据、配置修复、数据库备份迁移与所有内置谱面。

逐场景结果与媒体检查数值保存在 [release-validation.json](release-validation.json)。CI 已同步为 Debug、Release 都执行逻辑测试，并调用同一个完整发行打包脚本；远程 CI 本轮未触发。

Release 原生流程检查 **28/28**，通过真实 SDL 场景和事件管线执行：

- 首次启动进入教程提示，跳过后到主菜单并持久化提示状态。
- 曲库、练习选项、六页设置、教程、统计、工房属性、双区试玩、返回原工房。
- 表单新建中文曲名/中文路径谱面，验证音频复制、BPM、偏移和可选图片为空的元信息。
- 校准、正式舞台、暂停、结算。
- 实际七判定输入精确百万分；倒计时重试、Hold 中暂停恢复、游玩中窗口改为 1280×800。
- 回放与原局分数、偏差记录相同；辅助模式未增加正式游玩次数。
- 0.75 倍速分段练习只计算完整音符；整曲 2 倍速自动演示零 Miss；音频缺失正确返回曲库。

实机截图检查覆盖 960×540、1600×900、3840×2160；4K 的原 19 个场景全部通过，新增四个界面流程纳入最终版 28 项回归。检查截图文字、对齐、边界、属性弹窗、舞台对比和结算。验证输出均使用独立 `build/qa/*/userdata`，不写入玩家实际存档。

最终 ZIP 解压到带中文和空格的目录，从 `C:\Windows\Temp` 启动，2560×1440 下再次通过 **28/28** 流程检查，退出码为 0。进程模块检查确认 SDL3、SDL3_image、SQLite、JPEG 与 MSVC runtime 从解压包内加载。ZIP 完整性及逐文件 SHA256 校验通过。界面概览见 [实机截图](images/sakura-0.6-overview.jpg)。

媒体测试以同一 2 秒音源生成 WAV、MP3、FLAC、OGG，检查加载、2 秒时长、跳转 0.5 秒后继续播放以及频谱非零；四种全部通过。PNG、JPEG、WebP、BMP 均通过 SDL_image 加载并转换 PNG。

## 性能记录与范围

4K Release 场景检查中，CPU 更新与渲染提交的第 95 百分位：主菜单约 **1.35 ms**，曲库 **0.50 ms**，游戏 **1.55 ms**，工房试玩 **1.86 ms**。测量排除 `SDL_RenderPresent` 的垂直同步等待；完整帧间隔约 7.2–7.4 ms，与本机约 144 Hz 显示同步一致。

这些是本机抽样结果，不能解释为输入到显示的端到端延迟，也不代表所有显卡性能或相对旧版的百分比提速。逻辑测试和截图检查无法代替不同设备上的长期玩家手感测试。

## 交付边界

当前版本是完整离线可玩 **beta**。回放为 JSON，变速同时变调；现有程序合成曲包尚未经过人工听测与玩家难度定级。自动校准算法仍需玩家用自己的声卡、耳机和输入设备确认。

本轮不包含账号、在线排行榜、联网谱面市场、自动更新、背景视频或数字签名安装器；这些仍属于原路线图后续规划。当前可运行包使用散文件以保留离线导入和编辑能力。字体与第三方许可证随包提供。

数据库备份/恢复的损坏、迁移失败、未来版本与成功路径有逻辑测试；系统文件选择对话框的所有取消/权限组合，以及多小时游玩与全部硬件组合尚未穷尽。用户可通过游戏内备份保留自己的记录。
